# 06 · Connectors, tools and environment limits

What an agent working on this portfolio can reach, what it can't, and the workaround for each gap. This reflects the Claude project "Portfolio UI & Content Upgrades" as of 2026-09-27. Tools change, so re-check with your own tool list (and `ListConnectors` for claude.ai connectors) at the start of a task.

## What's available

| Need | Tool | Notes |
|---|---|---|
| Read and write the repo | `git` in the container + **GitHub MCP** (`mcp__github__*`) | No `gh` CLI. Use GitHub MCP for PRs, comments, reviews, check runs and job logs. Scope: `Harshith5299/portfolio` |
| Open a PR | `create_pull_request`, then `issue_write` (assignee `Harshith5299`) and `update_pull_request` (reviewer `Harshith5299`) | Start the body with the project attribution block your session gives you |
| Watch CI and reviews | `subscribe_pr_activity` (claude-code-remote) | Events wake the session; don't poll with `sleep` |
| Read CI logs | `pull_request_read` → `get_check_runs`, then `get_job_logs` / `get_check_run` | SonarCloud's summary comes through `get_check_run` (see [05-sonarcloud.md](05-sonarcloud.md)) |
| Vercel preview URL | The `vercel[bot]` comment on the PR (`pull_request_read` → `get_comments`), or the "Vercel Preview Comments" check | Preview URLs look like `https://portfolio-git-<branch-slug>-harshiths-projects-3b2f34b2.vercel.app` |
| Production deploy status | The `deploy-prod.yml` run on `main` (`actions_list` / `actions_get`) | It ends with a health check against harshithportfolio.com |
| A real browser | Playwright + preinstalled Chromium at `/opt/pw-browsers` | Don't run `playwright install`. Use it for local E2E and for screenshots of a local build |
| Shared memory | Project memory (`/tmp/claude/memory/team/silo/`, index `MEMORY.md`) | One fact per file with frontmatter; update, don't duplicate. Never store secrets |
| Shared files | `/mnt/project-files/` (when present) | e.g. `hero-cards/*.png` screenshots from #22. Files attached to replies must live here |
| Other threads' context | `list_thread_sessions`, `fetch_thread` (hearthbot) | Read earlier threads before re-asking Buddy something |
| User's own device | Remote Control (`list_devices`, `start_rc_session`) | For anything that needs Buddy's machine or signed-in accounts |

## claude.ai connectors

| Connector | State (2026-09-27) | Useful for |
|---|---|---|
| Google Drive | Installed, **not connected** | Reading Buddy's resume or docs directly instead of asking for uploads. Ask Buddy to connect it in Settings → Connectors if a task needs it |
| GitHub | Available via the GitHub MCP server | Everything repo-related |
| Vercel | **No Vercel connector.** Buddy manages env vars and settings in the Vercel dashboard himself | Ask Buddy for dashboard-only actions (env vars, analytics, spend limits), with exact click paths |
| LinkedIn | None for reading profiles (LinkedIn blocks automated reads) | Ask Buddy for "More → Save to PDF" of his profile |

When a task needs a service with no connector, search the registry (`SearchMcpRegistry`) and offer it with `suggest_connectors`, saying why it helps.

## Hard limits in the cloud container

| Blocked | Workaround |
|---|---|
| `harshithportfolio.com` and `*.vercel.app` previews (both blocked by the egress proxy, confirmed 2026-09-27) | Test a local production build with Playwright (`npm run test:e2e`, which builds and serves on :4173) and screenshot that. Check deploys through Actions. Ask Buddy to click through the preview and confirm anything that depends on production env vars (email delivery, "Generated by" answers). If a preview *is* reachable, run `BASE_URL=<preview> npm run test:e2e` |
| `sonarcloud.io` | Check-run summary via GitHub MCP; ask Buddy to paste issues |
| Vercel dashboard, logs, env vars | Ask Buddy. Log search terms to give him: `contact send failed`, `ask generation failed`, `bot_check_failed` |
| Real email / real Claude calls in tests | Fake them (local fake HTTP servers, `page.route` mocks) |

## Asking Buddy for things

Buddy reads the project on his phone between other work. When you need something only he can do:
- Say exactly what and where, as numbered clicks (for example "Vercel → Project → Settings → Environment Variables → Add, name `X`, tick Production and Preview, then redeploy").
- Explain where a key comes from (the provider's site, not Vercel).
- Ask for one thing at a time, and keep working on everything that doesn't depend on it.
